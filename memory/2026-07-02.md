# Memory - 2026-07-02

## What Was Done

1. **Fixed Duplicate Run/Continuation Checking:**
   - Modified `isSameOrNearDuplicateQuestion` and `isDuplicateRecentDisplayedQuestion` in `src/meetingAssistant.js` to perform token-based checking (using non-stopword tokens) rather than absolute word counts.
   - This ensures that if a question is updated or extended with meaningful new details (e.g. adding `"With incomplete information"` to `"Describe a situation where you managed a severe incident"`), it is correctly identified as a new/extended question rather than a duplicate, and is not skipped.
   - Updated associated unit tests in `test/meetingAssistant.test.js` to align with the new behavior.

2. **Fixed Punctuation-Resilient Overlap Merging:**
   - Modified `mergeFragmentBoundary` in `src/pineconeClient.js` and `mergeUtteranceText` in `src/meetingAssistant.js`.
   - Previously, matching of overlapping words between consecutive transcription turns failed if one had terminal punctuation (e.g. `customer satisfaction?` matching with `satisfaction when...`).
   - Now, punctuation is stripped during comparison, and the final punctuation is merged correctly by prioritizing `?`, then `.`, and appending it to the reconstructed string.
   - This prevents issues where transcription turn-splits caused the latter half of continuous sentences to be extracted as separate, incomplete standalone questions (e.g. `"satisfaction when resources are constrained."` instead of the full combined question).

3. **Interview Cue Settle Delay / Debouncer:**
   - Modified `getIntentSettleDelay`, `addPartialTranscript`, and `handleProFinalTranscriptGate` in `src/meetingAssistant.js`.
   - Now, when an interview prompt cue (e.g., `"tell me about a time"`, `"describe a time"`, `"can you"`, etc.) is detected, and the system is using a production settle delay (`>= 500` ms), the settling/debounce delay is increased to **2000 ms**.
   - If the transcription engine splits the speaker's question into multiple distinct turns with different `itemId` values (due to brief pauses or speech segment boundaries), any new incoming partial or final speech segment will **automatically clear all pending timers for previous segments**.
   - This ensures that if the interviewer pauses briefly mid-sentence, Clyde will hold off on executing or rendering draft card answers until the interviewer has fully finished speaking (2 seconds of quiet).
   - Added a corresponding unit test in `test/meetingAssistant.test.js` to verify this 2000ms delay behavior.
